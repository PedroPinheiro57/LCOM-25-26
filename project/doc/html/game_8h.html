Detailed Description

Central game-state machine: structs, state tags, and controller API.

The game is split across two VMs. The host owns the authoritative game state and drives the logic; the client forwards raw input over the serial link and renders whatever the host reports back.

All state transitions happen through the functions declared here. External code should treat game_t as read-only and access it only via game_get_state.
