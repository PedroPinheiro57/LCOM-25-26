Detailed Description

Serial communication protocol for the two-VM Battleship session.

Each message consists of a single-byte type tag followed by a fixed- length payload (which may be zero bytes for simple signals). The receiver assembles bytes through proto_feed_byte until a complete message is available.

Message flow overview:

  • Host and client exchange MSG_HELLO / MSG_HELLO_ACK to establish the connection.
  • During ship placement the client mirrors its actions via MSG_SHIP_PLACE and signals completion with MSG_DONE_PLACING.
  • During combat, the active player sends MSG_ATTACK; the host replies with the result embedded in the same message type.
  • Cursor positions are streamed with MSG_CURSOR so each side can show where the other player is hovering.

Feeds one byte into the protocol parser.

Call this from the UART interrupt handler for every received byte. When the function returns true a complete, decoded message has been written to msg_out and the state has been reset automatically.

Parameters
sParser state (call get_rx_state for the singleton).
bByte just received from the UART.
msg_outFilled with the decoded message when the return value is true.
Returns
true if a full message is ready, false if more bytes are needed.
